= C4 architecture model ownership and evidence — 0.1.3

`docs/architecture/workspace.dsl` is the canonical Tavi Assets owned model. `architecture/workspace.dsl` is kept synchronized for the existing 0.1.1 source checkout path (checked in `tools/verify_contracts.py`). Do not develop a separate competing architecture here.

== Code-grounded Level 3 inventory

* `AssetCoreL3`: `core.py` validator, installer, stage recovery, registry and resolver. These are function/class responsibility slices within a **single module**, not claims of separate deployable processes.
* `CatalogL3`: `catalog.py` catalog reader, store service, deny-paid adapter and unavailable purchase boundary.
* `StorefrontL3`: `preview.py` local loopback HTTP handler, `web/main.js` browser UI.
* `HostAdapterL3`: `host.py` trusted-grant Python test adapter, not a Tavi native host method.

LoopRD/Wallet, TaviX, Tavi and applications are shown only as opaque systems. No arrows imply functioning cross-project runtime integration. The edges in the model map to inspected Python/JavaScript calls and local HTTP requests. Browser is part of a local preview, not a TaviX extension container.

* `Stage Recovery` (within `AssetCoreL3`) maps to `AssetManager._recover_locked()` and `recover()`, which inspect the current registry under an OS-held lock, remove exact-name incomplete temporary files and leave finalized inactive pack versions inaccessible. No automatic entitlement grant occurs.

The public ZipRunner spec does not mandate this model; this is a **ZipRunner extension / local project policy** requirement.
