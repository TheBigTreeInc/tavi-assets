= Tavi Assets — portable embeddable runtime reference
:toc:

== Ownership and status

This is a **Tavi Assets-owned** JavaScript ES module implementation of a limited asset service. It can run in Node 22 or a secure WebView/browser with `crypto.subtle`, `TextDecoder`, `btoa` and `atob`. It is independent of Python; the Python engine/storefront is retained and still tested. It is *not* installed or hosted by any version of Tavi in this package.

Tavi must provide trusted storage and identity adapters, settings/navigation integration, extension-sandbox session identity and installation approval. Tavi must NOT duplicate the asset registry, pack validator or preferences engine. The host-side `AssetService` and `TrustedAssetHostBridge` are privileged and must never be handed to an extension. The existing `sdk/client.mjs` is the *unprivileged* consumer SDK exposed to a permitted TaviX game.

== Host-owned lifecycle API

[source,js]
----
import {AssetService,TrustedAssetHostBridge} from './portable_service/index.mjs';
import {MemoryAssetStorage} from './portable_service/index.mjs';

const service = new AssetService({
  storage: new MemoryAssetStorage(), // demo only: non-persistent
  authorizeInstall: async ({packId,version,origin}) => false // default-deny until host verifies policy
});
// Tavi constructs the trusted session context; extension cannot choose identity/grants.
const bridge = new TrustedAssetHostBridge(service, async trustedSession => null);
----

An approved host supplies `{manifest, files: Record<string, Uint8Array>, origin}` from a vetted source. `AssetService.install()` verifies identity, content hash, media signatures and conservative SVG markup, calls an injected host authorization policy (including the normalized manifest SHA-256 and host-vetted source identity) and activates via an atomic storage transaction. All installed resources are reverified on read in this reference; no arbitrary file paths or install method are exposed via `assets.*`.

`portable_service/storage.mjs` provides a memory test adapter; `portable_service/node-file-storage.mjs` provides a bounded **Node-only** persistent reference adapter using one atomic-replace snapshot. Its 8 MiB limit, in-memory Base64 transport and fail-closed crash lock are **not** production-grade for larger packs, recoverable updates or mobile storage. Native device adapters for Windows and Android and IndexedDB/browser storage are unimplemented; the host should supply a secure, storage-atomic adapter with efficient binary blob storage. It must preserve user/private state and keep entitlements separately authoritative in LoopRD.

== Selection and updates

Preference precedence is `application override -> global preference -> pack default`. The `setGlobalPreference()` operation is trusted-host Settings only; `assets.preferences.set` writes an application override, with host-granted customize permission and host-owned user consent. Variant values unknown to a new pack version fall back while leaving previously stored preferences intact. The same version may not be silently replaced by different bytes. Updates are checked before activation; failures leave the previous version intact.

The runtime does not implement remote catalog discovery, background fetching, production host approval policy, publisher signatures, a production first-party storefront UI module, cross-device sync, or wallet operations. A game's opaque card-rule references are **never executed** by this engine.

== Security and conformance scope

Test with `node tests/runtime_portable_smoke.mjs`. The source ZipRunner build `python tools/check.py` runs both Python and Node checks and validates the source contract. No UI/browser render, Android, Windows, Tavi end-to-end or Structurizr CLI result can be inferred from these tests. Stronger manifest/metadata parity, large-media and platform sandbox analysis remain pre-production requirements.

== Developer demonstration

Run `node examples/portable-runtime-demo.mjs` from the source root. The demo installs the free *Ink & Ember* fixture through the explicit *local test* approval callback, queries the subset of decks and sixteen jokers authorized by its bounded TaviX fixture grant, chooses an Indigo card back and reports media type. All three decks exist in the original pack but are not automatically authorized for the consumer. It is not a Tavi or TaviX production host session and never accesses Wallet.

== Cross-pack developer contract operations

The trusted bridge supports `assets.packs.list`, `assets.objects.discover` and `assets.composition.resolve` on top of the existing data-only runtime. The separately verified TaviX `tavix.asset-grants/v1` per-pack capabilities constrain every result; separate slot requests are checked individually. This does not implement combined image rendering, discovery in remote catalogs, purchases or per-variant entitlements. The Python preview host adapter has not yet been updated for these new methods; real Tavi availability remains unverified.

== Reference dependency readiness

`dependencies.mjs` verifies the versioned `tavi.assets.requirements/v1` declaration and resolves feature-level required/optional capabilities against validated, granted installed manifests. `TrustedAssetHostBridge` accepts `assets.dependencies.status` with `{}` only, taking the declaration from the verified TaviX manifest (or independently bound verified host requirements). It is not a purchasing, entitlement or installer API. `tavi.assets.dependencies/v1` feature advertisement is only demonstrated by the local fixture host, not production Tavi.

== TaviX per-pack grant adapter

`grants.mjs` checks a trusted TaviX host-context projection, extension identity/version/digest and requested per-pack capabilities/customization. `service.mjs` rechecks it on every host request, filters metadata/collection membership and independently authorizes each composition slot. Flat grants are rejected. This is still a local reference, not a real Tavi extension host or authority for paid content. See `docs/tavix-grant-integration.adoc`; especially note the current TaviX limit of 32 explicit capabilities per pack, which prevents full discovery of the 90-resource sample by one unchanged v1 grant.
